# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

FlowSync — a team task-management app built as a training project. Monorepo with two independent apps, each with its own dependencies and no shared root `package.json`:

- `backend/` — API on AdonisJS 7, SQLite (via `better-sqlite3`), token-based auth.
- `frontend/` — React 19 + Vite 8. Currently just the default Vite/React template (no routing, API client, or real UI wired up yet) — this repo is at an early scaffold stage (`s1/start`).

## Setup

```bash
cd backend && npm install && cp .env.example .env && node ace generate:key && node ace migration:run
cd frontend && npm install
```

## Commands

Run these from the respective `backend/` or `frontend/` directory (there is no root-level script runner).

**Backend:**
- `npm run dev` — start dev server with HMR at `http://localhost:3333`
- `npm test` — run Japa test suites (`node ace test`)
- `node ace test --files "tests/functional/some.spec.ts"` — run a single test file
- `npm run lint` / `npm run format` — ESLint / Prettier (AdonisJS shared configs)
- `npm run typecheck` — `tsc --noEmit`
- `node ace migration:run` / `node ace migration:rollback` — manage the SQLite schema
- `node ace make:controller|migration|validator` etc. — AdonisJS generators

**Frontend:**
- `npm run dev` — Vite dev server at `http://localhost:5173`
- `npm run build` — `tsc -b && vite build`
- `npm run lint` — oxlint

Run backend and frontend in separate terminals; the backend must stay running for the frontend to reach the API.

## Backend architecture (AdonisJS 7)

- **Subpath imports, not relative paths.** The `imports` map in `backend/package.json` defines `#controllers/*`, `#models/*`, `#validators/*`, `#transformers/*`, `#middleware/*`, `#services/*`, `#database/*`, `#start/*`, `#config/*`, etc. Always import via these aliases (e.g. `import User from '#models/user'`), matching the existing code.
- **Generated model schemas — do not hand-edit.** `database/schema.ts` is auto-generated by `node ace migration:run` from the migrations (schema generation is enabled in `config/database.ts`, rules in `database/schema_rules.ts`). Lucid models (`app/models/user.ts`) `compose()` these generated `*Schema` base classes rather than declaring columns directly. To change columns, write/modify a migration and re-run migrations — don't edit `schema.ts`.
- **Routing → controllers are indirected through a generated registry.** `start/routes.ts` imports `controllers` from `#generated/controllers` (produced by the `@tuyau/core` `indexEntities`/`generateRegistry` hooks configured in `adonisrc.ts`) rather than importing controller classes directly. Routes are grouped under `/api/v1`, with `auth` (`signup`, `login`) and `account` (`profile`, `logout`, guarded by `middleware.auth()`) sub-groups.
- **Custom response serialization.** `providers/api_provider.ts` registers a `serialize` method on every `HttpContext` (`ctx.serialize(...)`) that wraps responses as `{ data: ... }` and handles Lucid pagination metadata. Controllers return `serialize(...)` rather than plain objects — follow this pattern for new endpoints instead of returning raw data.
- **Transformers control what's exposed.** Response shaping goes through `BaseTransformer` subclasses in `app/transformers/` (e.g. `UserTransformer.transform(user)`), which `pick()` the allowed fields before serialization. Add a transformer when exposing a new model over the API.
- **Validation via VineJS.** Request validators live in `app/validators/` (e.g. `signupValidator`, `loginValidator` in `user.ts`) and are invoked with `request.validateUsing(...)` in controllers.
- **Auth.** Two guards are configured in `config/auth.ts`: `api` (token-based, default — via `@adonisjs/auth` access tokens, used for the JSON API) and `web` (session-based). Protect routes with `.use(middleware.auth())`; access the authenticated user in a handler via `auth.getUserOrFail()`.
- **Database.** SQLite only, file at `tmp/db.sqlite3`; other connections (Postgres/MySQL/MSSQL/libSQL) are stubbed out in `config/database.ts` but not installed.
- **Tests** use Japa (`@japa/runner`), configured in `adonisrc.ts` under two suites: `tests/unit/**/*.spec.ts` and `tests/functional/**/*.spec.ts` (functional tests boot a real HTTP server via `testUtils.httpServer()`, see `tests/bootstrap.ts`). Neither directory has test files yet.

## Frontend architecture (React + Vite)

Unmodified Vite React-TS template: `src/main.tsx` mounts `<App />` in `StrictMode`, `src/App.tsx` is placeholder scaffold content. Linting uses oxlint (`.oxlintrc.json`) rather than ESLint. There is no backend API client, router, or state layer wired in yet — these will need to be introduced when real features are built.

## Reglas de proceso
- Antes de tocar código: crear una rama nueva (`git checkout -b feat/<slug>`). Nunca commitear directo en `main`/`s1/start`.
- Al cerrar la tarea: usar la skill `/commit`, luego `gh pr create` con una descripción completa de los cambios en el cuerpo del PR.
- Después de abrir el PR: usar el subagente `adversarial-reviewer` sobre él, antes de darlo por terminado.
- No repitas ese resumen en el chat: la sesión se va a perder, el PR no. Responde solo con la URL del PR.
